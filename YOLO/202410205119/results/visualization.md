# 可视化说明

> 本文件说明 `results/figures/` 与 `results/predict/` 里每张图是什么、该怎么看、
> 以及它们分别对应验收要求的哪一项。

---

## 1. 为什么结果图要有这几类

目标检测的效果不能只看一个数字。完整的证据链需要覆盖三个层面：

| 层面 | 回答什么问题 | 对应文件 |
|---|---|---|
| **训练过程** | 模型到底学没学到东西？ | `figures/01_results.png` |
| **评估质量** | 分类有没有混淆？阈值该取多少？ | `figures/02_confusion_matrix.png`、`03_BoxPR_curve.png`、`04_BoxF1_curve.png` |
| **实际检测** | 框画得准不准？能不能用？ | `figures/06_val_labels.jpg`、`07_val_pred.jpg`、`predict/*.jpg` |

## 2. `results/figures/` 逐张说明

### 01_results.png —— 训练过程总览（★ 最重要）

**内容**：7 个子图，横轴都是 epoch（0~60）。

| 子图 | 含义 | 本项目的表现 |
|---|---|---|
| `train/box_loss` | 训练集边框回归损失 | 从 1.44 到 2.11，中段下降、末段回升 |
| `train/cls_loss` | 训练集分类损失 | **3.73 → 2.22 稳定下降**（学习有效的直接证据） |
| `train/dfl_loss` | 分布焦点损失 | 1.22 → 1.59，基本平稳 |
| `val/box_loss` / `val/cls_loss` / `val/dfl_loss` | 验证集对应损失 | 同步下降 |
| `metrics/precision` / `recall` / `mAP50` / `mAP50-95` | 验证集指标 | 末段 Precision 升至 1.000，mAP50 升至 0.380 |

**怎么看**：先看三条 loss 是否整体下降 —— 这是"训练确实在进行"的最基本证据。
6 张图的数据量下，末段曲线抖动属于正常现象，不应期待平滑收敛。

**用途（对应验收要求）**：Level 3「提交 Loss、Precision、Recall 等训练结果图」。

---

### 02_confusion_matrix.png —— 混淆矩阵

**内容**：行是真实类别，列是预测类别，共 4×4（含 background）。
对角线是分对的，非对角线是分错的。

**怎么看**：

- **对角线越深越好**；
- 最后一列 `background` 表示**漏检**（真实有目标但没检出来）；
- 最后一行 `background` 表示**误检**（本来没目标却检出来了）。

**本项目的表现**：`football` 行在对角线上有明显数值，说明球类检出正常；
`cola` 行大量落在 `background` 列，直接对应 `cola` 的 Recall = 0（整类漏检）。
这与 `results.csv` 里 `cola` mAP50 = 0.016 的数值完全一致，互相印证。

**用途**：Level 3「分析类别混淆情况」。

---

### 03_BoxPR_curve.png —— Precision-Recall 曲线

**内容**：横轴 Recall、纵轴 Precision，每个类别一条曲线。
**曲线下的面积就是 AP**，`mAP` 就是各类 AP 的平均。

**怎么看**：曲线越靠近右上角越好。
本项目中 `football` 的曲线有一定面积，`cola` 的曲线贴近坐标轴
（因为只有一个验证样本且未检出）。

---

### 04_BoxF1_curve.png —— F1-置信度曲线

**内容**：横轴是置信度阈值，纵轴是 F1 分数（Precision 与 Recall 的调和平均）。

**怎么看**：曲线的**峰值点**就是理论最优置信度阈值。

**实际用途**：本项目模型置信度整体偏低，推理时默认 0.25 会几乎检不到东西。
参考此曲线，把 `--conf` 调到 **0.10~0.20** 能得到更好的综合效果。
这是这张图在本项目中最实际的价值。

---

### 05_labels.jpg —— 数据集标签分布

**内容**：训练集的目标框在画面中的位置分布（左上图）、
框的宽高分布（右上图），以及各类别实例数量（下方条形图）。

**怎么看**：用来检查标注是否合理、数据是否有偏。

**本项目的表现**：目标框集中在画面中部（与实拍场景一致）；
类别条形图明显不均 —— `football` 最多、`cola` 只有 1 个，
这正是模型对 `cola` 效果差的根本原因。

---

### 06_val_labels.jpg vs 07_val_pred.jpg —— 验证集真值 vs 预测（★ 最直观）

这两张图是**同一批验证图片**的两种标注，必须成对看：

| 文件 | 内容 |
|---|---|
| `06_val_labels.jpg` | 标注**真值**（人工标的框） |
| `07_val_pred.jpg` | 模型**预测**结果（含类别名与置信度） |

**怎么看**：对比两者，预测框与真值框越接近说明效果越好。

**本项目的表现**：

- 上方图（`img02`，跨栏走廊）：真值有可乐瓶与远处足球；预测**未检出任何目标**（整图空白）；
- 下方图（`img06`，球门区）：真值有 2 个橙色球 + 1 个白黑足球；
  预测**成功检出 2 个橙色球**，其中一个置信度约 0.5，框位置准确。

**这张图的价值**：它诚实展示了模型"能检出什么、检不出什么" ——
而不是只挑成功案例。这正是本项目数据量不足的直观体现。

**用途**：Level 3「提交训练完成后的结果图」。

---

### 08_train_batch0.jpg —— 训练批次可视化

**内容**：训练时实际送入网络的批次图片，上面画着增强变换后的标注框。
12 张小图拼成一张（因为 `batch=2` 且启用了 `mosaic` 增强）。

**怎么看**：用来确认**标签位置是否正确**、**数据增强是否合理**。

**本项目的表现**：可以看到 mosaic 把多张图拼在了一起，
缩放、平移、HSV 抖动等增强都正常生效；框的位置贴合目标 ——
说明标注坐标没有错位（如果坐标写错，这里的框会明显偏靶）。

## 3. `results/predict/` 说明（Level 4 推理样例）

| 文件 | 内容 |
|---|---|
| `img02.jpg` | 推理结果图，**未检出目标**（原图保留），诚实反映局限 |
| `img06.jpg` | 推理结果图，**检出 2 个足球**，含框 + 类别名 + 置信度 |
| `detections.txt` | 推理的文本结果，与终端 `--print-dets` 输出完全一致 |

### detections.txt 内容

```text
img02.jpg | 未检测到目标（可尝试调低 --conf）
img06.jpg | 类别=football(id=2) 置信度=0.626 框=(218,210)-(294,283)
img06.jpg | 类别=football(id=2) 置信度=0.259 框=(180,193)-(240,262)
```

### 结果图上的三要素（Level 4 验收要求）

`img06.jpg` 上每个检出目标都包含：

1. **目标框** —— 黄色矩形，贴合橙色球轮廓；
2. **类别名称** —— 中文「足球」（模型类别表由权重文件读取，保证与训练一致）；
3. **置信度** —— 保留两位小数（`0.63` / `0.26`）。

> 中文标签是用 PIL 的 `ImageFont` 渲染的。原因是 OpenCV 的 `cv2.putText`
> 只支持 ASCII，直接写中文会变成问号。若系统找不到中文字体，
> `predict.py` 会自动回退为英文标签（`football 0.63`），不会报错。

### 如何自己生成一批推理样例

```bat
:: 在项目根目录执行
python predict.py --source dataset/images/val --conf 0.15 --print-dets --copy-to-results

:: 检测训练集之外的新图片（Level 4 核心要求）
python predict.py --source ..\new_photos --conf 0.15 --print-dets --copy-to-results
```

结果图会同时出现在：

- `runs/detect/predict/`（Ultralytics 原始输出）
- `results/predict/`（归档副本，便于提交）

## 4. Level 5 网页界面截图建议

由于本项目在无图形界面的环境中完成训练与推理，**未包含浏览器截图**。
提交前请在本地执行以下命令并截图：

```bat
pip install gradio
python results\code\gradio_app.py
:: 浏览器打开 http://127.0.0.1:7860
```

截图时建议让页面同时包含以下四项（正好对应 Level 5 的验收要求）：

| 截图需包含 | 对应验收要求 |
|---|---|
| 左侧「上传图片（原图）」 | 允许用户上传本地图片 |
| 右侧「检测结果」 | 显示检测后的结果图片 |
| 「识别结果明细」表格 | 列出识别出的目标类别与置信度 |
| 「检测摘要」文本框 | 汇总检测到几个目标 |

> **提示**：本项目模型置信度普遍偏低，建议先把页面上的**置信度滑块调到 0.10~0.20**，
> 再上传 `dataset/images/val/img06.jpg`，这样更容易截到有检测框的效果图。
